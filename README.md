# EatFlow · 这一顿吃什么

一个帮你 **10 秒决定这一顿吃什么** 的微信小程序：本地规则引擎 + 真实店铺数据 + 可解释推荐。

不是随机抽签，也不是"猜你喜欢"——它把你这次的真实约束（预算、时间、过敏原、想吃热乎的还是清淡的）当作硬条件先筛，再在剩下的候选里打分排序，并且为每一条推荐给出**为什么是它、为什么是现在、放弃了什么、下一步看什么**。

## 功能

- **口味档案**：过敏原、饮食禁忌、不喜欢的食材、口味偏好、预算、就餐方式（食堂 / 校外 / 自炊 / 外卖）
- **10 秒说清需求**：预算上限、可接受时长、场景、心情，支持"严格模式"
- **推荐 3 选 1**：硬约束过滤 → 软偏好打分 → 四段式可解释理由
- **真实位置数据**：浙江大学紫金港校区 160 家餐饮店铺、4 个锚点（校园中心 / 南门 / 东门 / 北门）共 640 条真实步行时间
- **位置可切换**：四个常用点一键切换，也可在地图上任意选点（云函数实时搜索）
- **转盘决定**：选择困难时，只在合格候选里摇
- **餐后反馈**：打分回写档案，推荐逐步贴近口味
- **历史记录**：每次决策与结果可回溯

## 目录结构

```
miniprogram/                微信小程序工程（原生，无第三方依赖）
  pages/                    11 个页面
  utils/recommend.js        规则引擎：硬约束 + 软偏好 + 解释生成
  utils/lbs.js              位置、候选池、严格过敏模式
  utils/geo.js              距离计算、品类先验
  utils/store.js            本地存储（统一 {data, error} 返回）
  data/pois-zju.js          烘焙的紫金港 POI 数据
  cloudfunctions/eatflowSearch/  腾讯位置服务代理云函数
EatFlow-产品设计-V1.0.md     产品设计文档
```

## 本地运行

1. 微信开发者工具 → 导入项目 → 选择 `miniprogram/` 目录
2. AppID 选「测试号」即可运行，内置离线数据包开箱可用
3. 想要任意位置实时搜索：在云开发中部署 `cloudfunctions/eatflowSearch`，并在云函数环境变量里配置 `LBS_KEY`（腾讯位置服务 Key，不入库）

## 数据来源与合规

- **数据来源**：`miniprogram/data/pois-zju.js`（160 家店铺、640 条步行时间）是课程演示用的
  **静态快照**，来源于腾讯位置服务 WebService API 的查询结果，查询时间点见文件头部注释。
- **使用限制**：该数据仅用于本课程的演示与学习，**不作对外分发，不作商业使用**；仓库中不含
  任何腾讯地图底图、瓦片、Logo 或审图号素材。如需将本项目用于公开或商业场景，请自行向
  [腾讯位置服务](https://lbs.qq.com/) 申请授权，并遵守其展示规范（地图 Logo、审图号标注等）。
- **密钥**：所有密钥均不入库。云函数从环境变量 `LBS_KEY` 读取，抓取脚本从 `TENCENT_LBS_KEY`
  读取，仓库历史中从未出现过任何 Key。
- **数据准确性**：价格、等待时间、营业时间为按品类估算，非实时数据；步行时间为查询时的快照。
  推荐结果不构成任何消费建议。
- **过敏安全**：严格过敏模式下，食材无法核验的店铺会被直接排除，并在界面上如实说明原因，
  不用"暂无数据"掩盖。
- **位置能力**：主路径使用预设常用点与 `chooseLocation` 由用户主动选点，不默认索取定位授权。

## 效果示例

同一组需求（预算 ≤ 25 且严格、35 分钟内、想吃热乎的）在不同位置的结果差异：南门 14 个合格、TOP3 清淡小吃；东门 39 个合格、TOP3 全变麻辣。同一家店在两个锚点的步行时间最大相差 37 分钟——位置是真的改变了结果，不是换了个排序。
