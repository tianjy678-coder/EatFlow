# EatFlow 接入真实位置数据

## 现在就能用的部分（不需要任何配置）

`data/pois-zju.js` 是已烘焙的**浙江大学紫金港校区周边 160 家真实店铺**，含从校园中心 / 南门 / 东门 / 北门四个锚点到每家店的**真实步行时间**（腾讯路径规划结果，非直线换算）。

- 来源：腾讯位置服务 WebService API
- 抓取时间：2026-10-29
- 覆盖范围：`data/areas.js` 里的 bbox
- 命中范围内时：零网络请求、零延迟、不消耗配额

## 想支持任意位置（需要开通云开发）

### 1. 开通云开发
微信开发者工具 → 云开发 → 按引导开通 → 复制**环境 ID**

### 2. 填入环境 ID
编辑 `app.js` 顶部：

```js
const CLOUD_ENV = '你的环境ID';   // 原来是空字符串
```

### 3. 部署云函数
在开发者工具里右键 `cloudfunctions/eatflowSearch` → 「上传并部署：云端安装依赖」

### 4. 配置 Key（**不要写进代码**）
云开发控制台 → 云函数 → `eatflowSearch` → 配置 → 环境变量 → 新增：

| 变量名 | 值 |
|---|---|
| `LBS_KEY` | 腾讯位置服务 WebService Key |

Key 只存在于服务端。小程序包里没有任何密钥，抓包也拿不到。

### 5. 为什么不需要配 request 合法域名
云函数在服务端发请求，不受小程序 `request` 域名白名单限制，所以不用去公众平台加 `apis.map.qq.com`。

## 配额与限流（实测）

| 项目 | 数值 |
|---|---|
| 日调用量 | 10,000 次 / 接口 / Key |
| 并发 | **5 次 / 秒 / 接口 / Key** |
| 距离矩阵计数方式 | **按元素数计** —— 每批最多 5 个 `to` 点，10 个点就会返回 120 |

因此单次决策只发 3 次请求：搜索 ×2 + 步行矩阵 ×1（5 个点）。
响应码 120 表示触发每秒限流，云函数内已做退避重试。

## 降级链路

```
离线真实数据包（命中 bbox）
   ↓ 未命中
本地网格缓存（0.005° ≈ 550m 格子，7 天）
   ↓ 未命中
云函数实时搜索
   ↓ 失败 / 未开通
内置示例池 + 明确提示「这是演示数据」
```

## 数据真实性的边界

| 字段 | 真实性 |
|---|---|
| 步行时间 | **真实**（路径规划）或按直线 ×1.3 绕行系数估算，UI 会标注 |
| 人均价格 | 品类先验估算（POI 不返回人均消费），标「人均按品类估算」 |
| 出餐时长 | 品类先验估算，标「出餐时长为估算」 |
| 营业时间 | **POI 不返回**，绝不显示「现在在营业」，改显示「营业时间未核实」 |
| 食材 / 过敏原 | **POI 不返回**，默认严格模式下填了过敏/禁忌就不推荐这些店 |

## 重新抓取数据

```bash
export TENCENT_LBS_KEY=你的Key
node fetch_zju.js      # 拉 POI
node fetch_matrix.js   # 算步行矩阵（约 3 分钟，受 5 次/秒限制）
node bake.js           # 烘焙成 data/pois-zju.js
```

脚本位于 `tools/lbs-fetch/`。
